# Changelog of the libretro core

What changed in the libretro core of this fork, newest first. Changes that come with a merge of upstream Vita3K are in upstream's own history; a merge is noted here with the upstream version it brought in.

## Unreleased

- OpenGL: a title loaded a second time in the same RetroArch session shows its picture again; it ran with sound and a black screen. The texture and framebuffer the core presents a frame with were kept across contents, and the second content's first frame used them from the first content's context, which was gone: the GL error that left made every surface the renderer created fail. They are now made in each context and deleted with it (#3, Shoegzer).
- The system firmware counts as installed only once its modules are in `vs0/sys/external/`: a `vs0` holding only `app` and `data` passed for it, so the firmware `.pup` was never installed and games that load firmware modules (Poltergeist's libfiber) were missing them (sco8487).
- A game's `eboot.bin` opened through RetroArch's file access (Android's file picker, Samba) is turned away with a message, as its folder is: the core went on to the folder, which it cannot read there, and only found the game's files missing (sco8487).
- Remove Content: new first option Delete user saves and trophies of removed titles, No (default), Saves only, Trophies only or Both, kept as set (its tooltip warns of that): a title removed there also has its saves or trophies deleted, every account's; a removal a crash cut short finishes with the choice it was turned on with. Not for an install that goes because Run Mode changed, and not counted in the sizes shown. The save folder and trophy sets are noted while a title runs (`ux0/libretro_pkg/userdata_<title ID>`); for a title not run since, its title ID's save folder and its install's trophy sets. Remove Content's tooltip ends "It does not remove original media." (#4, i30817).
- Content through RetroArch's file access (Android's file picker, Samba): the updates and DLC beside the game, and with Include Subdirectories below it, are listed as for a local game. The game's path came back from the core's path handling as `smb:/...` with its two slashes merged, so the core took the game's directory for a local one and found nothing in it; DLC in subdirectories were never looked for there either. The log says how many entries were found and which could not be read (sco8487).
- Direct with Cache: the list of the blocks a cache file holds (its `.idx`) is kept in memory and written when the game closes, not one line per block as it is read; after a crash that run's blocks are only decrypted again. It holds runs of blocks, `first-last`, a line each, and is written beside the old one and renamed over it, so a crash never leaves half a list, and the blocks' data and the new list are flushed to the disk before the rename, so a power cut right after closing cannot leave a list over blocks not yet written; the lists of earlier builds, a block a line, are read as they are (sco8487).
- Remove Content: sizes in MB and GB as the system's file manager shows them, of 1024 on Windows and of 1000 elsewhere, with at most three digits, rounded to the nearest and without trailing zeros, GB from what would be 1000 MB (0.977 GB, 1.5 GB, 2 GB); `titles.tsv` still holds bytes, so it works on any system (sco8487).
- The core's memory fault handler is installed again at the next load after a fault it did not handle had handed the signal back to the previous handler; before, it stayed off (sco8487).
- Android and Linux: loading a second game in the same RetroArch process no longer crashes RetroArch with no crash report. The JIT gave RetroArch's own thread an alternate signal stack and freed it when the core was unloaded, leaving the thread pointed at freed memory; the next signal on that thread could not be delivered and the kernel ended the process. The thread's own signal stack is now put back when the core closes (sco8487).
- A crash in RetroArch after a game was closed is no longer lost: the core's memory fault handler is removed with the game's memory and the one there was before is put back, where it stayed and worked on freed memory; a fault the core does not handle goes to that previous handler, so Android's tombstone (or the frontend's crash report) is written again, and on Windows the handler is no longer added again at each load (sco8487).
- Content: an update installed from the game's folder goes when Run Mode no longer installs, as the game and its DLC already did: it is read out of its PKG beside the game. One installed by loading its own PKG stays (sco8487).
- Content: a title started in another Run Mode than Direct with Cache has its Persistent Cache (`cache/pkg`) deleted first, as an installed copy already is when Run Mode no longer installs; the shader cache stays (sco8487).
- Remove Data is now a category of its own, Remove Content, right after Content, with what its heading said as the category's description; it is not shown when there is nothing in it (i30817).
- Firmware: each part that is not installed is installed at a game's load from its `.pup` in `system/vita3k`, so a prepared system directory works at the first start; System > Install Firmware is gone. A `.pup` loaded as content still installs over what is installed (i30817, sco8487).
- The core info file names the firmware packages `firmware.pup`, `preinst.pup` and `font.pup`, as the three download under the same name; any name the README lists still works (i30817).
- Content: Run Method is now Run Mode, the more common name (i30817, Shoegzer).
- Content: Remove Data is now a list at the end of Content, under a heading of its own: every title the core holds data of, each ON or OFF, the current title first and then the others, latest seen first. Each shows its name and ID and the size of what would be deleted, in MB or GB, the space it takes on the disk (a Persistent Cache only what it holds). Titles turned ON have their data deleted when the content is closed or reset. The list comes from one file, `ux0/libretro_pkg/titles.tsv`, so the start walks no directories; only the title that runs is measured, when it is new to the list or runs another way (once it is installed, and its entry then shows the size while it runs), and again when it is closed or reset. A title turned ON whose deletion a crash cut short or never started is deleted at the next start, before anything runs (i30817).
- Content: shorter descriptions of Run Method, Include Subdirectories and Remove Data, in active voice and without blank lines between the values, so they fit a phone's screen; Remove Data now says ON and OFF like Include Subdirectories, and that original media, saves and trophies stay (i30817, Shoegzer).
- Content: Update lists the versions in the game's directory as usual also while one installed by loading it on its own is there; it offered only that one and None. Each version is listed once, and choosing another sets the installed one aside, so it stays in the list. A set-aside update or DLC whose file is beside the game is deleted at the game's start, as the file has it all (it is read in place, or installed again), and loading an update or DLC on its own deletes a set-aside copy of the same one (i30817).
- Content: Run Method's description no longer ties it to Main Menu > Load Content, since it applies however the title is started (playlist, command line), says that updates and DLC in the title's directory are applied by default, and that they can also be loaded from elsewhere, which installs them whatever the Run Method (i30817).
- OpenGL: Vita3K's overlay is drawn over the picture as with Vulkan: the system dialogs, the notice of an earned trophy (its icon, grade and name, as in the standalone) and the shader compilation notice. A trophy earned after RetroArch reset the video context is announced once, not once for each reset (Shoegzer, issue #1).
- Content: Game Preload is now Run Method, with Direct, Direct with Cache and Installed, and the loaded game's entry is Current Title. The descriptions are rewritten as proposed: paragraphs, "directory" for "folder", no install paths in the menu (they are in the README), and Run Method's short enough for RetroArch's 1023 characters (Shoegzer).
- Content: Remove Data, an option of its own (off by default) above Current Title, offered whatever the Run Method. Turned on, it removes the running title's data when the title is closed or reset, and turns itself off again: the shader cache, the persistent cache, and everything installed for the title - the game, its update and its DLC; saves stay. Left on when the frontend did not close the title, it is turned off at the next start without removing anything (Shoegzer).
- Content: turning a DLC off, or choosing another update version or None, no longer deletes what was installed: it is set aside in `ux0/libretro_pkg/off` and comes back when chosen again; only Remove Data deletes. Update and DLC values say how they are used and then the state, "Installed (Enabled)" / "Installed (Disabled)" (or Direct); with one update its version is in the entry's name ("Update: 1.05"), with several the value names the version, and exactly one is in use (Shoegzer).
- Content: new option Include Subdirectories (off by default) also looks for the title's update and DLC in every directory below the title's, such as a directory per DLC with its license (i30817, Shoegzer).
- Content: an update or DLC loaded on its own now starts its installed game with the game's whole Content section (Current Title, Update, DLC); only Run Method was there.
- New category Trophies: Progress (the title, earned / total, percent) between empty rows, Display: Earn Status, Display: Grade, Display: Hidden and Sort Method (By Grade, By Name, By Earn Date), then the current title's trophies, each with its grade, name, description, ID and whether and when it was earned. A hidden trophy not earned yet is left out unless Display: Hidden is on. The list changes right away in the menu, appears as soon as the game opens its trophies, and follows trophies earned while playing. Text only: RetroArch's options cannot show the icons (Shoegzer).
- System > Install Firmware installs the `.pup` files in `system/vita3k` (os0 and vs0) on request, over what is installed; the core no longer installs firmware by itself at a start (Shoegzer).
- Accounts > Rename Active Account: a name entry by pad or keyboard, as in the Cemu core (Shoegzer).
- OpenGL: a frame the game writes with the CPU (Gravity Rush's first screen, for one) is shown; it was black (Shoegzer).
- Cross no longer also touches the middle of the front touch screen; the game gets only the button.
- The front and back cameras work: new option category Camera, with each camera showing RetroArch's camera (Host Camera, the default, as upstream defaults to the host's camera), an image from `system/vita3k/camera/`, or a solid colour, falling back in that order. The core's camera showed black only (Shoegzer, issue #1).
- New options under Network, as upstream has them: HTTP on or off, HTTP Timeout Attempts and Sleep, HTTP Read End Attempts and Sleep, and Adhoc Address, picked among the host's network interfaces with each one's subnet mask shown. The core used upstream's defaults and the first interface with no way to change them (Shoegzer, issue #1).
- New options under System: System Language (the console's language, which games use for their text; it was always English), Date Format and Time Format, as upstream has them under Date & Time and Language. The date and time themselves stay the host's, as in upstream (Shoegzer, issue #1).
- New option category Modules: each of the firmware's modules (`vs0/sys/external`) on or off, shown when Modules Mode is Auto & Manual or Manual. Until now there was no way to choose them, and Manual loaded none (Shoegzer, issue #1).
- New option category Accounts: Active Account (the account a game starts as, each with its own saves and trophies), Create Account and Remove Account. Account names are set in `system/vita3k/account_name.txt`, which lists every account. The account games saw before had no name; it is now named Vita3K, as upstream's first one is, and keeps its saves (Shoegzer, issue #1).
- Vulkan: a game that draws with gamma correction is no longer darker than in standalone Vita3K. Its frame is in an sRGB surface, and the core's blit turned its colours to linear on the way to RetroArch; it is copied as it is now, as upstream shows it (Shoegzer, issue #1).
- Vulkan: a frame the game writes into memory itself, with no rendered surface behind it (Gravity Rush's first screen, for one), is shown from memory as upstream does; the core showed nothing for it.
- The emulator's data, built-in shaders and system dialog icons are compiled into the core and unpacked into `system/vita3k/` at its first start and after an update of the core; nothing has to be copied next to it any more. A core from the buildbot is a single file and came without them (sco8487).
- New option category Content. It holds Game Preload (was System > Game PKG): Run Without Installing (the default), Persistent Cache (the same, keeping what was read for the next start) or Install. Below it, the loaded game's own entries: the game (installed, with Uninstall, or how it is run), its Update (one of the updates found, or None) and each DLC (Enabled or Disabled). A value says how the entry is used (Install, Forced Install, Run Without Installing or Persistent Cache) and the file it comes from. Updates and DLC are found beside the game or inside its folder, as PKG, VPK/ZIP or a NoNpDrm dump's own `patch/` and `addcont/` folders. A new game starts with the newest update and every DLC; when the update it ran with is taken out of the folder, the next lower version is used, or none. A change shows the message that the content has to be started again (sco8487).
- A game, its update and DLC follow Game Preload, whether they are a PKG, a VPK/ZIP or a folder: read where they lie as the game goes (a NoNpDrm one decrypted on the way), or installed. A game installed while Game Preload says otherwise is uninstalled at its next start, saves kept. An update or DLC installed by loading its own file is a Forced Install and stays installed whatever the mode. An installed update or DLC whose file is gone says so (sco8487).
- What is turned off in Content (a DLC set to Disabled, an update no longer chosen, the game set to Uninstall) is deleted when the content is closed, or at its next start if RetroArch did not get to close it. Reset closes the content and loads it again, so Game Preload and Content changes apply to it (sco8487).
- Run Without Installing and Persistent Cache start a game at once: the files it starts with are decrypted into place, every other file is a placeholder with no data, read out of the source as the game reads it. Persistent Cache keeps the blocks read, the start files included, so a next start decrypts nothing read before. What a run left laid out because RetroArch was killed or crashed is removed at the next load (sco8487).
- Installs decrypt each file as it is read out of the package and write it once, in its place; upstream's install wrote the package out encrypted and decrypted it into a second copy, about twice the game's size for a while. An update stays in `ux0/patch` and is laid over the game's files, never merged into them, so changing it no longer reinstalls the game (a game installed with a merged update by an earlier release is installed again once, the first time its update changes). A NoNpDrm update or DLC from a folder or VPK/ZIP is decrypted on install, and loading an update or DLC on its own installs it again, which mends a broken install (sco8487).
- Every mode checks the free space for the whole game first (Persistent Cache: what is not cached yet); when it does not fit, the game is not started or installed, and a message says how much is needed. Where RetroArch's system folder is on a file system without sparse files (FAT32, exFAT), Game Preload offers Install only, as the other two would take as much space as an install; the core tries that once with a small file and again only when the folder is on another file system, and deletes a Persistent Cache left from one that had them (sco8487).
- Licenses: a `work.bin` beside a PKG is taken only when its content ID is the PKG's; a NoNpDrm game without its `work.bin` says the license is missing and is not started (it was installed still encrypted and failed without a word); a DLC with no license next to it shows Inactive (no license) and is left alone (sco8487).
- No more decryption folders ending in `_dec` beside a game, update or DLC: a DLC read out of its PKG left one in `ux0/addcont/<title>`, which Content and the game saw as another DLC. Decrypting goes through `ux0/libretro_pkg` (sco8487).
- The game's start image (`sce_sys/pic0.png`) is shown from the moment the game starts until its first frame, as the standalone does, instead of a black screen (Vulkan; sco8487). Installing or unpacking a game happens before RetroArch shows anything from the core, so the image does not cover that.
- Linux: the core exports only the libretro API, and its calls into the C++ runtime it carries stay inside it. They went to RetroArch's own libstdc++ when that was loaded first, and on a system with GCC 16's it crashed while reading a PKG's license (Shoegzer, #1).
- A file next to a PKG under a license's name (`work.bin`, `<name>.rif`, `<content ID>.rif`) that is not the size of a license is no longer read as one: one larger than 2 KB overran a buffer and crashed RetroArch at once (Shoegzer, #1).
- A firmware `.pup` can be loaded from RetroArch like a game: the core installs it, whichever of the three packages it is and whatever its name, and says which parts are still missing (Shoegzer).
- New option GPU > Shader Compilation Overlay (on by default): turned off, the notice of shaders being compiled is no longer shown in the lower left corner of the picture. Other overlays stay (sco8487).
- The core no longer writes `libretro_trace_uwp.log`: a debugging aid of the original port that was appended to at every start and never trimmed, in a `vita3k` folder inside RetroArch's save directory that nothing else used. The same lines are in RetroArch's log. The core no longer asks for the save directory or the downloads directory, which it had no other use for (sco8487).
- The system dialogs are shown and answered with the pad: the save data list, system messages and the other dialogs a game opens through the Vita's common dialog, drawn over the picture by Vita3K's own overlay as in the standalone. The core never drew them, so a game that opened one waited for an answer forever (lim2222: a save list that never appeared). While a dialog is open the game gets no pad input. The same overlay brings the trophy and shader compilation notices. The dialogs' icons are in `system/vita3k/icons`, which the builds now ship. A dialog cannot be answered by touch.
- Save data and add-on content are where the standalone keeps them: `ux0/user/00/savedata/<title>` and `ux0/addcont/<title>`. The core had no user and no title in those paths, so every game saved into one shared folder, saves copied from the standalone were not found, and a game saw other games' add-on folders as its own (lim2222: a save that would not load, a game waiting on another game's add-on). Saves made with earlier builds are copied into a title's folder the first time it starts.
- A firmware that is there but incomplete (the preinstalled package or the fonts missing, as with folders copied from the standalone) is reported as that, naming the missing part, and no longer as "Firmware not found" (lim2222).
- The firmware packages are found whatever the case of their names, and under more names: a `.pup` with `preinst` in its name is the preinstalled package, one with `font` the fonts, any other the system firmware. A firmware saved as `psvupdat.pup` was not found where file names are case-sensitive (lim2222).
- Content behind RetroArch's VFS is loaded: a `saf://` path, as the Play Store RetroArch on Android gives for folders it was granted, is opened and listed through the frontend. That covers a `.vpk`, `.zip` or `.pkg` (installed or run without installing) and the licenses next to it; a game folder behind such a path is not supported yet, and the core says so. Not tested by anyone yet.
- Linux: the core no longer links libX11, libXext and libwayland-client, and builds without their headers: they were for the window surface the standalone makes, and the core makes none. It now loads where those libraries are absent.
- The libretro buildbot builds the Windows core too: its MSVC is too old for Vita3K, so the job cross-builds on Linux with clang-cl against the MSVC runtime and Windows SDK (`.ci/build-windows-cross.sh`), with OpenSSL, zlib and Boost.Filesystem built by the script instead of taken from vcpkg; OpenSSL there is built without its assembly. A GitHub workflow replays the job. The Windows builds on the Releases page are still made with MSVC.
- The core option texts can be translated through libretro's Crowdin project: the options header is on the standard template, with the `intl/` scripts and the upload and sync workflows. All texts are English until the first sync.
- Internal Resolution Multiplier reaches RetroArch: the images handed over take the size the picture was rendered at (they were fixed at 960x544, shrinking a 2x to 4x render back), and RetroArch is told the size when it changes.
- Audio: RetroArch gets one frame's worth per call, and the game's audio waits once about 64 ms is queued.
- Closing content and Reset stop GXM before the guest threads and join its display thread, clean the renderer up before it is freed and stop the audio ports first, as upstream's shutdown does.
- A NoNpDrm game in a `.zip` installs decrypted.
- Android: RetroArch no longer crashes over a missing built-in shader; the core reads its data files itself instead of through SDL, which sent a file it could not open to Java.

## Test build 2 - 2026-10-05, rebuilt on 6 and 7 October

- Merged up to upstream Vita3K v0.2.1 build 4123 (a5aa96572), from upstream of February, with its new renderer and overlay code. The core reports upstream's version.
- The repository holds the core only: the standalone app's Qt interface, updater and Android app are not part of it.
- PKG install: a game's PKG, its update or DLC is installed with upstream's installer. A game's PKG needs its license next to it (`<name>.zrif`, `<name>.rif`, `work.bin` or `<CONTENT_ID>.rif`) or already in `ux0/license`; a license can also keep its PSN name, and every 512-byte `.bin` near the PKG is checked for the content ID.
- New option System > Game PKG, by default Run Without Installing: the game runs straight from its PKG, each file decrypted the first time the game reads it. Install keeps the full install; updates and DLC are still installed.
- Vulkan on RetroArch's device: the core makes the device itself, with what memory mapping needs, takes RetroArch's queue lock for every submit, and copies each frame for RetroArch on the render thread. This fixed the lost GPU device with memory mapping. Memory Mapping is Double Buffer by default, as upstream, and Page Table works.
- Audio: a game's audio ports are mixed instead of played one after another, each converted to 48 kHz, and no silence is made up. Before, sound warbled and ran at the wrong tempo.
- Android: games no longer crash at start. SDL asked Android's Java side for the app's package name, which a core does not have.
- PKG installs no longer stop at 80%.
- macOS cores for Apple Silicon and Intel, with Vulkan through RetroArch's MoltenVK.
- Linux cores are built on Ubuntu 24.04 (glibc 2.39).
- The core info file is in each zip.
